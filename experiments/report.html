S1 · ISO download on another device during a video call

Call = 50 pps × 172 B UDP echo. Added p95 latency = loaded p95 RTT minus idle median RTT; steady excludes the first 7 s (classification warm-up). The download runs on a different device from the call, and CAKE already isolates devices from each other, so this is the easy case: a fixed-rate static CAKE does very well here. The adaptive controller trades a little latency for ~5% more throughput (it probes the real capacity instead of trusting a configured number).

S7 · Video call while the same device uploads a backup on a port no rule knows

Call = 250 pps × 1200 B UDP echo (~2.4 Mbit/s each way). The same laptop runs a 16-stream backup upload and an ISO download on ports no rule knows. In the best-effort tin, flow fairness gives the call only ~1/17 of the uplink, less than it needs, so it loses packets. Rules recognise the call only on its well-known port; a classifier that recognises behaviour can move it to the voice tin on any port. Compare the loss and steady columns between rules and the AI classifier on the unusual port.
